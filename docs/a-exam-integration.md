## C와 구현 전 합의할 항목

다음은 **제안이며 아직 구현/확정된 통신 규격이 아닙니다.**

1. 기존 LIST_DEVICES 폴링은 유지. 시험 이벤트는 별도 TLS 관리자 연결에서 REGISTER의 subscribe_exam:true로 구독하고 원문 EXAM_EVENT를 수신. 기존 GUI 연결에는 예고 없는 이벤트를 보내지 않음.
2. 현재 exam_mode는 DEVICE_LIST의 각 PC 및 기존 STATUS_UPDATE의 device에 포함. 재등록·단절 시 미확인으로 무효화. 명령 성공 응답 뒤에만 확정하고 다른 관리자도 상태를 조회/구독하도록 함.
3. RTT는 B의 상태·독립 rtt_timestamp와 서버의 측정값 수신 신선도를 함께 확인. 서버 수신만 갱신됐다고 이전 RTT가 새 측정이라고 표시하지 않음. PC 시계 오차가 큰 경우 C의 보수적 숨김 유지 여부 합의.
4. 시험 이벤트의 감독자별 조회 범위는 현재 관리자 공통 토큰으로 개인별 구분이 불가능. 현 단계에서는 인증된 관리자 전체를 동일 감독 역할로 볼지 합의. 시험별 권한 분리가 필요하면 별도 인증 설계부터 합의.

합의 후 서버 중계·지원 플래그와 C 구독/경고·이력을 각 담당자가 구현하고 공동 검증합니다. A는 C 소스를 수정하지 않습니다.

## DB 운영

로컬 서버는 기본 `runtime/server-audit.sqlite3`를 사용하며 `--audit-db`로 지정합니다. 소스 관리에서 제외되어 있습니다. 저장소는 서버만 접근하며 GUI에 DB 파일을 공유하지 않습니다. 이벤트·명령은 기본 30일 보관하고 시작 및 새 기록 처리 때 정리합니다. 실행자는 관리자 접속별 임의 ID로 기록하며, 공통 관리자 토큰으로 개인의 신원을 확인했다고 표현하지 않습니다.

DB를 열 수 없으면 서버 시작을 중단합니다. 접수/저장 중 DB 오류가 나면 해당 세션을 닫고 명령을 자동 재전송하지 않습니다. 접수 기록만 있는 명령은 결과 미확인입니다. DB 보존이 재시작 후 중복 방지의 조건입니다. DB 삭제/교체 시 기록 보장이 사라집니다.

기존 EC2 systemd의 ProtectHome=read-only 설정에서는 홈 아래 DB 쓰기가 차단됩니다. 배포 시 A가 전용 쓰기 경로(예: /var/lib/cloudnet-control)를 서비스 사용자 소유·권한 0700으로 준비하고 `--audit-db`를 그 경로로 지정해야 합니다. 기존 인증정보는 그대로 사용합니다. 이번 작업에서 서비스 설정은 변경하지 않았습니다.
