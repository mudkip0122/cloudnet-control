## TLS·토큰 통합 후 추가 검증 (2026-10-30)

위 표는 통합 이전 기록입니다. 프로젝트 Agent의 ID 유지·수집·로그·재접속 기능을 보존하고 PC-02의 TLS·토큰 연결을 통합한 후 다음을 추가 확인했습니다.

- `python -m tests.smoke_tls` 통과. 임시 인증서와 테스트 토큰을 사용하는 실제 TLS 서버에서 잘못된 토큰 거절, 정상 등록, 실제 CPU 측정값 전송, 연결 단절 후 같은 프로세스의 TLS 재연결·재등록·재전송 확인.
- `python -m tests.smoke_live` 통과. 기존 평문 로컬 서버·실제 수집·GUI 반영·오프라인 전환 유지 확인.
- 통합한 프로젝트 Agent로 `32.236.13.91:5000`에 `PC-02` ID와 기존 인증서·토큰을 사용해 등록 성공 확인. 이 확인은 `--live` 없는 1회 등록이며 계속 실행하는 Agent를 남기지 않았습니다.

실제 EC2 서버 재시작 후 장기 복구, 실제 PC 3대 동시 접속, 30분 안정성, Windows 부팅 자동 실행·원격 제어는 이번 추가 검증에 포함하지 않았습니다. 실제 인증정보는 Git에서 제외된 `secrets/`에만 보관합니다.

## B 담당 2주차 보완 및 재검증 (2026-11-09)

환경: Windows, 프로젝트 `.venv`, Python 3.11, psutil 7.2.2. 아래는 이번에 직접 실행한 결과입니다.

| 항목 | 방법 | 결과 |
|---|---|---|
| 전체 단위 테스트 | `python -m unittest discover -s tests -v` | 29개 통과 |
| Heartbeat 주기·등록 협상 | 잘못된 값 거절, 서버 값 우선, 재등록 시 이전 값 초기화 | 통과 |
| 수집 지연·스레드 정리 | 수집 2.3초 지연 중 1초 Heartbeat·ACK, ERROR 후 작업 종료 | 통과 |
| TLS 통합 | `python -m tests.smoke_tls` | 잘못된 토큰 종료 코드 2, TLS 등록·Heartbeat/ACK·실제 CPU 값·단절 후 재인증 통과 |
| 반복 서버 재시작 | `python -m tests.smoke_reconnect` | 실제 서버 3회 재시작, 같은 Agent 프로세스·ID로 새 측정값 전송, 중복 ID 종료 코드 2 통과 |
| 실제 Agent 프로세스 3개 | `python -m tests.smoke_agents` | 고유 ID 3개·실제 수집 동시 전송, 중복 거절, 한 Agent 종료 후 나머지 최신 값 유지 통과 |
| 기존 EC2 주소 접속 | PC-02, 기존 CA·토큰, 등록 전용 실행 | 2026-11-09 14:00 KST TCP 연결 시간 초과, 종료 코드 1. 인증 단계 도달 못함 |

Windows venv의 Python 실행기가 자식 인터프리터를 남기는 테스트 정리 문제도 발견해, 위 통합 테스트에서 자신이 시작한 프로세스 트리를 정리하도록 수정했습니다. TLS 테스트는 수정 후 정리까지 포함해 종료 코드 0으로 재확인했습니다.

Heartbeat는 기존 미지원 서버와의 호환을 위해 기본 비활성입니다. 지원 서버가 REGISTER_RESULT의 `heartbeat_interval`을 제공하거나 실행 시 `--heartbeat-interval 5`를 지정하면 활성화합니다. ACK는 선택 사항이며 ACK 타임아웃 기반 장애 감지는 구현 범위에 포함하지 않습니다.

PC 세 개 검증은 **한 PC에서 실행한 Agent 프로세스 3개**입니다. 실제 PC 3대·서로 다른 네트워크·EC2 서버 재시작·배포 서버의 15초 오프라인 판정은 검증하지 못했습니다. EC2 현재 주소·리슨 포트·보안 그룹 확인과 Heartbeat 계약 반영은 A에게 인계합니다. 상세 공동 검증 체크리스트는 [B 2주차 인계](week2-b-handoff.md)를 참조하세요.

## 프로세스 조회·보호 종료 확장 (2026-11-09)

- 전체 단위 테스트 40개 통과. 기본·사용자 추가 보호 이름, Agent·조상·시스템 PID, 다른 사용자, 실행 파일 정보 불명, Windows 중요 프로세스·판정 불가, PID 생성 시각 불일치, 권한 오류, 종료 확인 대기 결과, 페이지 프레임 크기, 비활성·대상·만료·중복 명령 거절을 검증했습니다.
- `python -m tests.smoke_process_control` 통과. 임시 TLS 서버와 실제 Agent에서 목록 페이지 수신, Agent 보호, 생성 시각 불일치 거절, 자체 생성한 대기용 Python 프로세스의 실제 종료, 중복 명령 거절을 확인했습니다. 일반 사용자 앱·시스템 프로세스는 실제 종료하지 않았습니다.
- `python -m tests.smoke_tls` 재통과. 기존 TLS 등록·Heartbeat·실제 측정값·재접속·재인증 동작을 유지했습니다.
- 실제 조회는 수백 개의 프로세스를 열거해 접근할 수 없는 항목도 null·보호 상태로 반환하는 것을 확인했습니다. 조회 시 Agent 조상 정보는 한 번 수집하고, 종료 시에는 새로 검증합니다.
- A 서버의 관리자 권한 검증·명령 중계와 C GUI 연동, 실제 EC2 경유 프로세스 제어는 아직 수행하지 않았습니다. 구현 계약은 [프로세스 제어 안내](process-control.md)에 있습니다.
