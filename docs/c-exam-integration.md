# C GUI 연동 작업 상태

기준: B `3a091ef`, 통합 브랜치 `integration/c-exam-batch-control`.

교수님 피드백을 반영해 기존 C 구현을 `c/week3-dashboard`에도 병합했습니다. 추가 기능을 C 3주차 범위로 관리하며, A 연동·경고/감지 이력 구현·공동 검증·main 병합은 아래 미완료 항목을 따릅니다.

## 구현

- PC 목록에 CPU(%), RAM(%), 업로드/다운로드(Mbps), 서버 RTT(ms)를 PC ID별로 표시.
- RTT는 유효한 ok/숫자/독립 측정 시각일 때 표시. pending/timeout을 구분하고 오프라인·지연·미지원은 숨김.
- 프로세스 화면의 ‘같은 이름 그룹’으로 casefold 그룹 및 개수·합산 메모리 표시. 펼치면 PID·사용자·메모리·생성 시각·보호 사유 확인. 이름 미확인 항목은 개별 표시.
- 그룹 또는 여러 PID 선택 후 일괄 종료. 확인한 PID·생성 시각만 전송, 보호 항목 제외, 최대 100개, 대상 변경 시 취소. 결과는 별도 영역에 PID별로 보존하고 재조회. 자동 종료 재시도 없음.
- 시험 모드 창에 시험 ID·금지 실행 파일·검사 간격과 켜기/끄기/조회 명령 구현. TLS 관리자 연결 필요. 성공 응답 전 상태 미확인, 대상 연결 변경 후 상태 조회.
- B 소스는 브랜치 병합으로 가져왔으며 C 작업에서 수정하지 않음. 서버·공통 프로토콜·운영 인증정보 변경 없음.

## A와 합의 및 통합이 필요한 항목 — 완료 아님

현재 main 서버에는 새 action, EXAM_EVENT 중계, RTT 수신 지원이 없다. 현 상태에서 새 Agent 시험 실행 파일을 운영에 적용하지 않는다.

1. A→C EXAM_EVENT 전달 방식 및 다른 관리자가 변경한 exam_mode 상태 전달 형식은 B 인계 문서에서도 미합의 사항이다. 원문 이벤트 구독 수신을 사용할지 A 담당과 확인한 뒤 경고·감지 이력·event_id 중복 억제·감시 상태 갱신을 연결해야 한다. 현재 시험 창은 명령 결과를 통한 상태만 표시하며 실시간 감시 경고는 미구현이다.
2. RTT 시계 오차 및 서버 수신 시각 기준은 A와 합의가 필요하다. 현재 C는 기존 METRICS 신선도(6초)와 독립 rtt_timestamp 범위(-6~8초)를 모두 확인하는 보수적 표시를 사용한다. 시계가 어긋나면 수치를 숨긴다. 서버 수신 시각만으로 RTT가 새 값이라고 간주하지 않는다.
3. A 통합 브랜치를 합친 뒤 실제 TLS 서버→B→C의 모드 켜기·감지·끄기, 일괄 종료 및 RTT 지연을 검증한다. 시험용 자체 생성 프로세스만 종료한다.
4. 실제 PC 3대와 서버 공동 검증은 아직 수행하지 않았다. A 지원 및 규격 합의·공동 검증 전 main 병합을 보류한다.

## 검증 명령

```powershell
.\.venv\Scripts\python.exe -m unittest discover -q
.\.venv\Scripts\python.exe -m tests.smoke_gui_processes
.\.venv\Scripts\python.exe -m tests.smoke_dashboard
```

`tests.test_c_integration`은 요청 식별 고정·100개 제한·보호 항목 제외·시험 입력 검증·RTT 독립 만료·실제 Tk 그룹 펼치기·일괄 종료 결과·확인창 중 대상 변경 취소를 검증한다. 로컬 검증은 운영 서버 및 실제 PC 3대 공동 검증을 대체하지 않는다.

검증 결과: 전체 단위·로컬 통합 테스트 135개 통과. 프로세스 GUI 및 3대 대시보드 스모크 통과. 운영 서버에는 접속하거나 배포하지 않았다.
