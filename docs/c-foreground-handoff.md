# C: Chrome 활성 창 이탈·복귀 경고와 이력

기준: B `b6f76c0` 및 [B 인계 문서](b-foreground-handoff.md). A 신규 전경 지원은 `18139f1`, C를 포함한 공동 검증은 `fdb7bb2`이며 최신 C 브랜치에도 병합했습니다.
작업 브랜치: `c/week3-dashboard`. B·A 변경은 각 담당자의 커밋을 병합했고 C는 GUI·C 테스트·C 문서만 직접 수정했습니다. 기존 인증정보는 유지합니다.

## C 구현

- EXAM_EVENT v1의 EXAM_WINDOW_CHANGED에서 left를 ‘Chrome 이탈’, returned를 ‘Chrome 복귀’로 표시합니다. 전후 프로세스의 PID·이름·생성 시각과 전환 방향을 검증합니다.
- 메인 화면에 PC ID·시험 ID·대상 프로세스 이름/PID·시각을 표시합니다. 이탈은 붉은색, 복귀는 녹색이며 둘 다 감지 이력입니다. 금지 프로세스 경고와 분리하고 현재 실행이나 부정행위 확정으로 표현하지 않습니다.
- 시험 모드 창의 최근 500개 이력에 전환 전후 프로그램/PID와 전경 감시 상태를 표시합니다. 최근 4096개 event_id 중복 억제는 기존 규칙을 따릅니다.
- FOREGROUND_MONITOR_STATUS의 unavailable은 ‘감시 공백 · 활성 창 확인 불가’, ok는 ‘활성 창 조회 가능 (최근 수신 상태)’로 표시합니다. 프로세스 MONITOR_STATUS와 독립적으로 처리합니다.
- 선택 PC 상세와 시험 모드 창에 오프라인·이벤트 연결 단절·모드 미확인·시험 꺼짐·지원/첫 상태 대기를 구분합니다. 이벤트가 없다는 이유로 정상 응시나 Chrome 사용 중을 추정하지 않습니다.
- Agent 세션 ID 변경·모드 재설정/끄기·재접속·구독 공백 때 현재 전경 상태를 무효화하고 이력은 보존합니다. 세션 변경 후 GET_EXAM_STATUS로 다시 확인합니다. 이전 구독 세대의 대기 이벤트는 이력에만 반영합니다.
- 첫 관찰과 공백 복구에서 이탈을 소급 생성하거나 공백 전후의 이탈 지속 시간을 계산하지 않습니다. Chrome 내부 창/탭·URL·화면·키 입력 감시는 없습니다.
- 별도 TLS 관리자 연결에 subscribe_exam:true와 A 확정 규격의 subscribe_status:true를 함께 설정합니다.

## A에게 전달 및 현재 상태

> A fdb7bb2를 최신 C 브랜치에 병합했습니다. A 18139f1의 두 전경 이벤트 검증·저장·중계와 exam_foreground_v1:true 지원을 확인했습니다. C의 이벤트 파서·경고·이력·감시 공백·초기화는 기존 규격 그대로이며 추가 필드 변경 요청은 없습니다. 다음 공동 검증은 최신 서버/Agent 적용 후 실제 Windows Chrome 창 전환입니다.

A c5ecfef/646d171에서는 새 전경 이벤트가 미지원이었으나 **18139f1부터 지원**합니다. B는 exam_foreground_v1이 true일 때만 활성 창 감시를 시작합니다. 이미 실행 중인 이전 서버/Agent에는 새 코드가 자동 반영되지 않으므로 새 버전으로 재실행해야 합니다. C는 서버 허용 목록이나 지원 플래그를 직접 변경하지 않았습니다.

A 646d171의 기존 시험 이벤트 TLS 검증에 이어, fdb7bb2에는 실제 C 수신 코드와 A TLS 서버를 사용하는 새 전경 이벤트 검증이 포함됐습니다. 이탈·복귀·공백·복구·중복 억제·끄기 후 상태 초기화/이력 보존을 확인하는 범위이며 실제 사용자 Windows 창 전환 시연과는 구분합니다.

## 검증

`tests.test_gui_foreground`는 전환·중복 억제·경고 분리·감시 공백과 복구·첫 관찰·세션/시험 초기화·이력 보존·이전 세대 이벤트·잘못된 방향/식별자를 검증합니다. `tests.test_week3_dashboard`는 실제 Tk 위젯의 전환 경고·이력·감시 공백을 검증합니다.

신규 A→C 이벤트 중계는 로컬 TLS에서 검증됐으며 실제 Windows 데스크톱 전환·EC2·실제 PC 3대 검증은 남아 있습니다. TLS 테스트에서도 활성 창 조회 API는 모의하므로 실제 사용자 데스크톱 검증으로 표시하지 않습니다.

초기 C 검증은 전체 202개 및 일반/샘플 대시보드·프로세스 GUI 스모크 통과였습니다. A fdb7bb2 병합 후 C 환경에서도 전체 211개 통과를 재확인했습니다. 실제 C 수신 코드↔A TLS 서버의 신규 전경 중계까지 포함하며 Windows 활성 창 조회는 모의합니다. 실제 사용자 창 전환이나 사용자 앱 종료 시연은 수행하지 않았습니다.
