```text
┌ CloudNet Control ────────────────────────────────────┐
│ 서버 주소·포트 / TLS 모드 / 관리자 인증 상태           │
│ 서버 연결 상태 / 오류 및 재시도 안내                  │
│ 최근 목록 변경: PC 접속·해제 / 전체 목록 동기화        │
├ PC 목록 ─────────────────────────────────────────────┤
│ PC 이름 / ID | 상태 | 송신 Mbps | 수신 Mbps | 측정 UTC │
├ 선택 PC 상세 ─────────────────────────────────────────┤
│ 이름 / ID, 상태, 송수신, 측정·수신 UTC, 경과 시간     │
│ [PC 종료] [PC 재부팅] · PC 제어 미연동 / 확인창만 표시 │
│ [프로세스 목록] · TLS 관리자 인증 연결 필요 여부 안내 │
├ CPU·RAM % 카드 ────────┬ PC별 네트워크 차트 ──────────┤
│ 결측: —               │ 과거 시계열 / 상태 안내       │

```

### 화면 상태

| 상태 | 조건 | 표시·동작 |
|---|---|---|
| 연결 중 | 시작 후 첫 목록 수신 전 | 서버 연결 중, 초기 전체 목록 대기 |
| 정상 | 등록 및 전체 목록 수신 성공 | PC 수, 선택 상세, 측정값 표시 |
| 데이터 없음 | 빈 목록 / PC의 첫 측정 전 | Agent 접속 대기 / 데이터 없음, 값은 `—` |
| 오프라인 | 서버가 `online=false` 보고 | 행 유지, 현재 측정값 숨김 |
| 서버 단절 | 연결 거절·시간 초과·EOF | 목록 유지, 현재 값 숨김, 3초 후 재연결 |
| 인증 실패 | `UNAUTHORIZED` 또는 등록 거절 | 관리자 토큰 확인 안내, 자동 재시도 중단 |
| 인증서 오류 | CA·이름·유효기간 검증 실패 | 인증서 확인 안내, 자동 재시도 중단 |
| TLS 오류 | 그 외 TLS 연결 실패 | TLS 오류 표시, 3초 후 재연결 |
| 응답 오류 | 잘못된 메시지·목록 필드 | 응답 오류 표시, 3초 후 재연결 |
| 지연·시각 오류 | 측정 6초 초과 또는 잘못된 시각 | 원래 시각 유지, 현재 사용률 `—` |

종료·재부팅 버튼은 온라인 PC 한 대를 선택한 상태에서만 확인창을 열며, 그 외에는 대상 선택 안내를 표시합니다.
확인창에 PC 이름, 고유 ID, 작업명을 표시하고 취소할 수 있습니다. 현재는 설계 미리보기로 실제 명령을 전송하지 않습니다.
5주차에 명령 ID·중복 방지·권한 검증·결과 추적을 연동해야 합니다.

## A에게 공유할 메시지·필드

| 방향 | 메시지 | 필수 내용 / GUI 용도 |
|---|---|---|
| GUI → 서버 | `REGISTER` | `role=admin`, TLS 모드에서는 `token`; 관리자 인증 |
| 서버 → GUI | `REGISTER_RESULT` | `ok=true`; 인증 성공 |
| 서버 → GUI | `ERROR` | `code=UNAUTHORIZED`; 인증 실패. 응답 원문·토큰은 화면에 노출하지 않음 |
| GUI → 서버 | `LIST_DEVICES` | 인증 직후와 이후 1초마다 전체 목록 요청 |
| 서버 → GUI | `DEVICE_LIST` | `devices` 배열, 빈 배열 허용 |
| PC 항목 | 목록·상세 공통 | `pc_id`(고유 문자열), `pc_name`, `online`(bool), `last_received`(UTC), `metrics`(객체 또는 null) |
| 측정 항목 | 상세·차트 | `timestamp`(UTC), `cpu_percent`, `ram_percent`, `upload_mbps`, `download_mbps`; 결측은 null |

현재 접속·해제 표시는 전체 목록 간 `online` 변화를 비교해 반영합니다. 서버 push 이벤트는 사용하지 않으며 조회 사이에 발생하고 끝난 짧은 접속은 기록되지 않을 수 있습니다.
복구 시에도 인증을 새로 수행하고 전체 목록으로 교체하므로 서버 재시작 후 사라진 PC는 GUI에서도 제거됩니다.
영속 이벤트 이력이나 push가 필요하면 A와 별도 메시지 규격을 합의해야 합니다.

## B에게 공유할 단위·주기

`metrics-spec.md`를 기준으로 CPU·RAM은 전체 사용률 0~100 %, 네트워크는 Agent 기준 송신·수신 Mbps입니다.
Mbps = 누적 바이트 차이 × 8 / 실제 경과 초 / 1,000,000. 기본 수집·전송 2초, GUI 목록 조회 1초, 큐 확인 100ms입니다.
화면에서 CPU·RAM은 소수 1자리, 네트워크는 소수 2자리로 표시합니다. `0`은 활동 없음, `null`은 결측이며 `—`로 표시합니다.
PC ID는 재연결 후에도 동일해야 합니다. 첫 CPU 호출과 첫 네트워크 차분은 준비 구간으로 취급합니다.

## 실행

저장소 루트에서 의존성을 설치합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

로컬 확인은 서로 다른 터미널에서 실행합니다. 이 모드는 인증 없는 로컬 개발 모드입니다.

```powershell
.\.venv\Scripts\python.exe -m server.main
.\.venv\Scripts\python.exe -m agent.main --live --pc-id local-pc-1
.\.venv\Scripts\python.exe -m admin_gui.main
```

TLS 실행 예시입니다. 탄력적 IP `13.238.97.144`에 연결하고 기존 인증서 이름 `32.236.13.91`로 검증합니다.
서버 인증서·개인키는 서버에서만 사용합니다. GUI에는 CA와 관리자 토큰, Agent에는 CA와 별도의 Agent 토큰을 배포합니다.

```powershell
# 서버: 기존 인증서·개인키·PC별 토큰 매핑 auth.json 사용 (재발급 불필요)
.\.venv\Scripts\python.exe -m server.main --host 0.0.0.0 --port 5000 --tls-cert secrets/server.pem --tls-key secrets/server.key --auth-file secrets/auth.json

# 관리자 PC
.\.venv\Scripts\python.exe -m admin_gui.main --host 13.238.97.144 --server-name 32.236.13.91 --port 5000 --ca-file secrets/ca.pem --token-file secrets/admin-token.txt

# 각 Agent PC (PC마다 고유 ID)
.\.venv\Scripts\python.exe -m agent.main --host 13.238.97.144 --server-name 32.236.13.91 --port 5000 --ca-file secrets/ca.pem --token-file secrets/agent-token.txt --live --pc-id pc-001
```
