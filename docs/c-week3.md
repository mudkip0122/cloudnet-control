# C 3주차 — 대시보드와 그래프

작업 브랜치: `c/week3-dashboard`. 교수님 피드백으로 PC 3대 비교·시험 모드 버튼과 경고·프로세스 그룹과 일괄 종료·RTT 표시도 3주차 C 범위에 포함합니다. 별도로 준비한 통합 브랜치의 기존 C 구현과 B `3a091ef`를 병합했습니다. 서버·공통 메시지 규격은 변경하지 않으며 A 연동과 main 병합은 대기 상태입니다.

## 교수님 피드백 추가 범위

| 추가 요구사항 | C 구현 상태 | 남은 검증/연동 |
|---|---|---|
| PC 3대 비교 | 목록에서 PC별 CPU·RAM·네트워크·RTT·상태·시각 비교 | 실제 PC 3대 공동 검증 |
| 시험 모드 버튼 | 선택 PC 상세의 ‘시험 모드’ → 켜기·끄기·상태 새로고침 | A 새 명령 중계 지원 |
| 시험 모드 경고·감지 이력 | 미구현 | A→C 이벤트 전달 형식 합의 후 구현·연동 |
| 프로세스 그룹·일괄 종료 | 프로세스 창의 ‘같은 이름 그룹’, ‘선택 그룹·PID 일괄 종료’, PID별 결과 | A STOP_PROCESSES 지원 및 실제 TLS 통합 검증 |
| RTT 표시 | 목록과 상세의 서버 RTT(ms), 미수신/지연/오프라인 구분 | A RTT_PONG·METRICS 중계와 시각 기준 합의 |

추가 기능이 화면에 표시되는 것과 A·B·C 통합 동작 완료는 구분합니다. 현재 로컬 서버는 새 시험/일괄 종료 명령과 RTT를 지원하지 않으므로 거절 또는 미지원 값이 표시될 수 있습니다. 기존 개별 프로세스 조회·종료는 유지합니다. 상세 인계와 합의 대기는 [C 연동 문서](c-exam-integration.md)를 따릅니다.

병합 후 검증: 전체 테스트 142개, 대시보드 스모크, 프로세스 GUI 스모크 모두 통과.

## 구현 결과

| 요구사항 | 구현 |
|---|---|
| 선택 PC 상세 | CPU·RAM %, 업로드·다운로드 Mbps, Agent 측정 UTC, 서버 최근 수신 UTC, GUI 목록 수신 UTC, 각 경과 시간 |
| Matplotlib 그래프 | CPU·RAM 시계열 및 업로드·다운로드 시계열, 시간축 UTC, CPU·RAM 축 0~100%, 트래픽 축 자동 조정 |
| PC별 버퍼 | PC ID별 최근 180개 고유 측정값. 기본 2초 수집이면 약 6분. 동일/역순 시각은 추가하지 않고 목록에서 사라진 PC의 버퍼 제거 |
| 갱신 제한 | 같은 PC의 일반 데이터 변경은 최대 1초 1회. 대기 콜백은 한 개만 유지. 선택 PC·상태 변경은 즉시 반영. Figure·Axes·Line 객체 재사용 |
| 결측·단절 | null·음수·무한대·NaN·범위 밖 사용률은 결측. 0과 구분. 결측·6초 초과 간격·확인된 단절 뒤에는 선을 연결하지 않음 |
| 오래된 값 | 측정 후 6초 초과·시각 오류·오프라인·서버 단절 때 현재 값은 —, 차트는 이전 측정 기록으로 표시 |
| 제어 제한 | 지연·단절·오프라인에서는 프로세스 버튼과 PC 제어 미리보기 버튼 비활성. 프로세스 창도 사용 불가 상태 반영 |

서버 최근 수신 시각에는 Heartbeat도 반영될 수 있으므로 측정 시각과 구분합니다. GUI 목록 수신 시각은 Tk 메인 스레드가 전체 목록을 적용한 시각입니다. 단절 중에는 마지막 시각을 유지하며 경과 시간은 증가합니다. 샘플 모드는 고정 예시임을 표시합니다.

차트의 180개 제한은 최근 측정 개수이며 서버 영속 이력 조회 기능이 아닙니다. 서버 재시작으로 목록에서 PC가 사라지면 해당 로컬 기록도 제거합니다. 이벤트 기반 이력·경고는 4주차 범위입니다.

## 실행

저장소 루트에서:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m admin_gui.sample
```

실제 서버 실행 방법은 [C 로컬 가이드](c-local-guide.md)와 [1·2주차 인계](c-week1-week2.md)를 따릅니다. 기존 인증서·토큰을 사용합니다. PC 종료·재부팅은 기존처럼 확인창 미리보기이며 실제 제어를 전송하지 않습니다.

## 검증과 남은 확인

```powershell
.\.venv\Scripts\python.exe -m unittest discover -q
.\.venv\Scripts\python.exe -m tests.smoke_dashboard
.\.venv\Scripts\python.exe -m tests.smoke_dashboard --sample
.\.venv\Scripts\python.exe -m tests.smoke_live
```

- `tests.test_charts`: PC별 버퍼 상한, 중복·역순 시각, 결측·비정상 값·단절 간격, PC 3개에 2초 간격 30분 분량의 합성 데이터 901회 입력 검증.
- `tests.test_week3_dashboard`: 실제 Tk/Matplotlib 위젯에서 같은 PC 이름을 가진 서로 다른 ID 3개 전환, CPU·RAM과 그래프 대응, 단절 시 제어 비활성·이전 기록 표시, 갱신 제한·객체 재사용 검증.
- 30분 분량 입력은 빠르게 수행하는 합성 데이터 검증입니다. 실제 30분 실행이나 운영 프로세스 메모리 측정을 완료했다는 뜻이 아닙니다.
- 실제 PC 3대·배포 서버 동시 연결과 장시간 실행은 A·B가 준비되면 공동 확인합니다.

검증 결과: 전체 테스트 101개 통과. `smoke_dashboard`, `smoke_dashboard --sample`, `smoke_live` 모두 통과. 로컬 실제 Agent의 측정값 표시와 오프라인 전환을 확인했습니다. A/B 통합 브랜치 병합 및 운영 배포는 대기 상태입니다.

## 사용자와 로컬 화면 확인

기존 로컬 검증용 인증정보를 재사용해 TLS 서버 1개와 동일 컴퓨터의 Agent 3개를 실행했습니다. 실제 PC 3대 검증과 구분합니다.

- 선택 PC의 CPU·RAM·업로드·다운로드·측정 시각 표시 확인.
- CPU·RAM 및 네트워크 그래프 표시와 갱신 확인.
- 그래프 갱신 중 PC 선택·창 이동 응답성 확인. 실제 장시간 메모리 측정은 미완료.
- 상세와 그래프의 PC ID 일치 확인. PC ID가 아래쪽에서 가려지는 배치를 상단 고정 표시로 수정 후 사용자 확인. PC 전환 후 과거 기록 유지의 수동 확인은 별도 미완료이며 자동 테스트로 PC별 버퍼 분리를 검증함.
- 검증용 PC-03만 중지해 나머지 2개 온라인 유지, PC-03 오프라인·현재 값 숨김·이전 기록 표시·프로세스 버튼 비활성 확인. 이후 PC-03 재실행 및 측정 갱신 확인.
- 측정 UTC와 GUI 목록 수신 UTC 및 경과 시간의 구분·갱신 확인.
- 프로세스 필드·확인 불가 정보·보호 항목의 종료 버튼 비활성 확인.
- 전체 페이지 수신·명령/PC ID 대조·부분 수신 후 단절 차단은 `tests.test_gui_processes` 9개 및 GUI 스모크 검증 통과. 빠른 수신 중 버튼 비활성의 사용자 수동 확인은 대기.

1주차의 A에게 메시지·필드 전달과 B의 단위·주기 확인은 문서·구현 대조까지 완료했으며 담당자의 수신·검토 확인은 대기입니다. 2주차의 A 확정 운영 주소·신뢰 인증서 접속 확인 역시 로컬 TLS 검증과 구분해 미완료로 유지합니다. 관리자 앱 인증은 관리자 토큰이며 Windows 관리자 비밀번호와 별개입니다.
