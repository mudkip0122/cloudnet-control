# 관리자 프로세스 목록·보호 종료

## 화면 사용

관리자 GUI에서 온라인 PC를 선택하고 상세 영역의 **프로세스 목록**을 누릅니다.
별도 창에서 **새로고침**하면 PID·이름·사용자·메모리(MiB)·종료 가능 여부·보호 이유가 표시됩니다.
읽을 수 없는 필드는 `확인 불가`, 보호 이유는 한국어 설명으로 표시합니다.

`can_stop=false`이면 **선택 프로세스 종료** 버튼이 비활성화됩니다. 종료 가능한 행을 선택하면 확인창에
PC 이름·ID, 프로세스 이름·PID·사용자·생성 시각과 미저장 내용 손실 안내가 표시됩니다.
취소하면 요청하지 않으며, 확인하면 선택한 목록 행의 `pid`와 `create_time`을 그대로 함께 보냅니다.
Agent가 실제 종료 직전에 생성 시각과 보호 정책을 다시 검증합니다.
PC 종료·재부팅 버튼은 기존 설계 미리보기이며 이 프로세스 종료 기능과 별개입니다.

## 연결 조건

GUI·서버·Agent의 TLS 연결과 역할별 인증이 필요합니다.
평문 로컬 모니터링·샘플 모드에서는 메인 화면의 프로세스 목록 버튼이 비활성화되고, 버튼 아래에 TLS 인증 필요 또는 샘플 모드 안내가 표시됩니다.
실행 중인 예전 서버·Agent는 새 코드를 자동으로 읽지 않으므로 해당 버전으로 재실행해야 합니다.
서버 실행과 관리자 TLS 접속은 [1·2주차 실행 안내](c-week1-week2.md)를 따릅니다.
Agent에는 추가로 `--enable-process-control`을 지정합니다.

```powershell
.\.venv\Scripts\python.exe -m agent.main --host 13.238.97.144 --server-name 32.236.13.91 --port 5000 --ca-file secrets/server.crt --token-file secrets/agent-token.txt --pc-id PC-03 --live --enable-process-control
```

CA 파일은 실제 배포된 인증서 체인과 일치해야 합니다. 탄력적 IP에 연결하면서 기존 인증서 이름을 유지하므로 `--server-name 32.236.13.91`을 지정합니다. GUI도 같은 옵션을 지원하며 프로세스 전용 연결에도 전달합니다.
현재 변경은 로컬 코드와 임시 TLS 통합 검증 범위이며, EC2에 배포하거나 실제 사용자 앱을 종료하지 않았습니다.

## 메시지와 동작

- B의 [프로세스 제어 규격](process-control.md)에 맞춰 고유 `command_id`, `target_id`, 30초 후 `expires_at`을 사용합니다.
- `LIST_PROCESSES`: 명령·PC ID를 검증하고 모든 페이지를 모은 뒤 목록을 한 번에 교체합니다. 빈 목록도 정상 완료입니다.
- METRICS·HEARTBEAT·다른 명령 결과를 목록에 섞지 않습니다. 중복 페이지·페이지 수 변경·중복 PID·잘못된 필드는 오류로 처리합니다.
- 페이지 누락·타임아웃·단절 시 불완전한 목록을 게시하지 않습니다. 기존 목록이 남아 있어도 종료할 수 없습니다.
- `STOP_PROCESS`: PID·생성 시각을 함께 보내고 결과를 기다리는 동안 중복 요청을 막습니다.
- 성공·거절·오류 결과를 받은 뒤 전체 목록을 새로 요청합니다. `TERMINATED`는 종료 확인, `TERMINATION_REQUESTED`는 종료 완료 미확인으로 표시합니다.
- 결과 미수신 시 종료 여부 불명확으로 표시하고 재조회합니다. 종료 명령을 자동 재전송하지 않습니다.
- PC 변경·오프라인·관리자 단절 시 목록을 무효화합니다. 이전 대상·연결 상태의 늦은 응답은 표시하지 않습니다.

통신은 모니터링과 분리된 관리자 연결·전용 worker·결과 queue를 사용합니다. 명령 결과를 버리지 않으며,
Tk 위젯·확인창은 메인 스레드에서만 갱신합니다. 창 종료 시 소켓 shutdown 후 worker 종료를 기다립니다.

## 서버 연동

`server/main.py`에 TLS 관리자 명령을 활성 TLS Agent로 전달하고 결과를 요청한 관리자에게만 반환하는 중계를 추가했습니다.
송신 잠금으로 프레임이 섞이지 않도록 하고 PC ID·Agent 세션·명령 ID를 확인합니다.
명령 ID는 60초간 중복을 제한하며 관리자 단절 시 대기 명령을 제거합니다.
A의 PC별 Agent 토큰 매핑과 별도 관리자 토큰 인증을 유지합니다. 서버 실행은 `--tls-cert`·`--tls-key`·`--auth-file`을 사용합니다. 영속 감사 기록은 후속 작업입니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe -m tests.smoke_gui_processes
.\.venv\Scripts\python.exe -m tests.smoke_gui_process_tls
```

페이지 조립·누락·중복·다른 대상 응답, 시스템 PID의 생성 시각 0, 보호 행 버튼 비활성화,
확인·취소, 정확한 PID·생성 시각 전송, 결과 후 새로고침, 대상 변경 후 늦은 응답 무시를 검증했습니다.
임시 CA·TLS 서버·실제 Agent·GUI 통합 검증에서는 40행을 넘는 목록을 수신하고,
테스트가 생성한 대기용 Python 프로세스만 종료한 뒤 자동 재조회에서 해당 PID가 사라짐을 확인했습니다.
