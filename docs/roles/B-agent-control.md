# B 담당 — Agent·원격 제어

담당: B (사용자)

## 담당 목표와 범위

Windows PC의 상태·프로세스 목록을 수집하고, 연결이 끊기면 자동 복구하며, 인증된 경로로 받은 프로세스 종료·PC 종료·재부팅 명령을 검증·실행하는 Agent를 완성합니다. 핵심 프로세스와 추가 지정 앱은 종료하지 않습니다. 주 작업 경로는 `agent/`입니다.

1~2주차와 별도 프로세스 확장 체크박스는 2026-11-09 기준 B의 로컬 구현·검증 상태를 반영했습니다. 실제 PC 3대·EC2 공동 검증은 아직 완료되지 않았습니다. 상세 결과와 인계 계약은 [B 2주차 결과](../week2-b-handoff.md), 전체 일정은 [프로젝트 계획서](../project-plan.md)를 따릅니다. 다른 3주차 이후 체크박스는 작업 배정안이며, 구현이 선행된 경우에도 주차 전체 완료를 뜻하지 않습니다.

## 먼저 할 일

1. A·C와 Python 버전과 메시지 규격을 확인합니다.
2. 서버 없이 CPU·RAM 값을 수집하는 작은 프로그램을 만듭니다.
3. A의 로컬 서버에 등록하고 측정값 한 건을 전송합니다.
4. 측정값을 1~2초 간격으로 전송해 C의 화면 표시를 확인합니다.
5. 연결 종료 후 자동 재접속을 확인하고 TLS를 검증하며 EC2로 연결합니다.

## 주차별 작업과 완료 기준

### 1주 차: Agent 골격과 데이터 정의

- [x] CLI 설정 읽기, 시작·종료, 로그 기록 구조 준비 (`.env` 자동 로딩 제외)
- [x] PC별 고유 ID를 생성·보존하는 방법 정의; 재시작해도 ID 유지
- [x] PC 이름, OS 정보, 부팅 식별값의 수집 방법 정의 (실제 전송은 공통 규격 합의 후 추가)
- [x] CPU·RAM·송수신 속도의 필드·단위·결측값 정의 및 공통 규격 문서화 (배포 서버와 최종 일치 확인은 공동 검증)
- [ ] 테스트 PC와 소유자 동의 범위를 정리하고 실제 제어 기본값은 비활성화

**산출물:** Agent 골격, 측정값 예시, Windows 개발 환경 안내.

**완료 기준:** 로컬에서 CPU·RAM 수집 결과를 확인하고 서버 등록에 필요한 필드를 설명할 수 있습니다.

### 2주 차: 연결·인증·재접속

- [x] 서버로 아웃바운드 TCP/TLS 연결하고 CA·서버 이름 검증
- [x] 공통 `common/` 송수신 코드로 등록·인증 응답 처리
- [x] 선택적 Heartbeat 전송과 연결 종료·수신 오류 처리 (EC2 수신 지원 확인 필요)
- [x] 지수 백오프에 따른 재접속 구현; 재접속 상한과 종료 동작 정의
- [x] 수집과 독립적인 수신·Heartbeat 작업 구성
- [x] 동시 송신 직렬화 및 재접속 시 이전 소켓·작업 정리
- [x] 인증 실패·인증서 오류와 일시적 네트워크 장애를 구분해 로그 기록

**완료 기준:** PC 3대가 고유 ID로 접속하고, 서버 재시작 후 수동 조작 없이 다시 등록됩니다. 인증 실패를 무한 고속 재시도하지 않습니다.

**현재 판정:** B의 로컬 구현·검증 완료. 실제 Agent 프로세스 3개 동시 연결, 중복 ID 거절, 로컬 서버 3회 재시작 복구 및 임시 TLS 서버 재인증 통과. 실제 PC 3대·EC2 완료 기준은 미충족입니다. 기존 EC2 주소는 시간 초과였고, 새 주소 `3.26.40.204:5000`은 TCP 연결 후 인증서 IP 불일치로 실패했습니다. A가 고정 주소와 일치하는 인증서를 배포하면 B는 재등록·측정 전송을 확인합니다.

### 3주 차: 시스템 정보 수집

- [ ] `psutil`로 CPU·RAM 사용률을 수집하고 첫 CPU 측정 처리 기준 정의
- [ ] 네트워크 누적 송수신 바이트의 차분과 실제 경과 시간으로 Mbps 계산
- [ ] 경과 시간은 단조 시계를 사용하고 카운터 초기화·감소를 처리
- [ ] 첫 네트워크 샘플과 측정 불가 값을 0 또는 결측 중 합의한 방식으로 표현
- [ ] UTC 측정 시각과 PC ID를 포함해 1~2초마다 전송
- [ ] 수집 오류 시 전체 Agent가 종료되지 않도록 처리

**완료 기준:** Windows 작업 관리자와 측정 경향을 비교하고, 부하 변화가 GUI의 해당 PC에 표시됩니다. 순간 측정값의 완전한 일치보다 측정 간격과 계산 근거를 검증합니다.

### 4주 차: 장애 검증

- [ ] 네트워크 차단·복구, 서버 종료·재시작 시나리오 수행
- [ ] 단절 중 오래된 측정값이 무제한 쌓이지 않도록 처리 정책 구현
- [ ] 재접속 후 같은 PC ID와 최신 측정값으로 복구
- [ ] CPU·RAM 부하 및 연결 단절 시나리오를 A·C에게 제공
- [ ] 로그에 토큰·개인키가 남지 않는지 확인

**완료 기준:** 연결 복구 후 수집·전송이 재개되고, 중복 작업 스레드나 반복 등록 문제가 발생하지 않습니다.

### 프로세스 조회·보호 종료 확장 (3주차 조회 연동, 5주차 제어 통합)

- [x] OS에서 열거 가능한 전체 프로세스 목록 제공; PID·이름·사용자·생성 시각·메모리·상태·종료 가능 여부·차단 이유 포함
- [x] 접근 불가 정보는 null로 표시하고 정보 부족 대상은 종료 차단
- [x] 시스템 PID·핵심 이름·Windows 폴더 실행 파일·Windows 중요 프로세스·Agent/조상·다른 사용자 보호
- [x] `--protect-process`로 추가 보호 이름 설정; 종료 직전 정책 재검증
- [x] PID·생성 시각을 함께 검증하고 단일 PID 종료, 종료 확인·요청 상태 구분
- [x] TLS·토큰·live 모드와 명시적 `--enable-process-control` 조건에서 원격 프로세스 명령 활성화
- [x] 대상·명령 ID·만료 검사, 60초 메모리 중복 방지 및 최대 4096개 한도 적용
- [x] 단위 테스트 총 40개, 임시 TLS 서버에서 자체 생성한 테스트 프로세스 실제 종료 검증
- [ ] A 서버의 관리자 권한 검증·중계·영속 감사 기록과 연동, Agent 재시작 후 중복 방지 범위 확정
- [ ] C의 목록 페이지 조합·종료 확인창·보호 이유·결과 표시와 연동
- [ ] 실제 PC 3대·EC2에서 보호 대상 거절과 테스트 프로세스 종료 확인

**완료 기준:** GUI에서 목록을 조회하고 보호 대상은 Agent에서 거절하며, 선택한 테스트 프로세스만 종료하고 결과가 해당 명령에 대응합니다. 일반 앱 강제 종료 시 미저장 내용 손실 가능성을 안내합니다. 상세 계약은 [프로세스 제어 안내](../process-control.md)를 따릅니다.

### 5주 차: PC 종료·재부팅

- [ ] 프로세스 명령과 구분한 PC 종료·재부팅 action 규격을 A와 확정하고 허용 목록에 추가
- [ ] 대상 PC ID, 명령 ID, 만료 시각, 중복 실행 여부 확인
- [ ] 재접속·Agent 재시작을 포함한 중복 방지 범위를 A와 확정하고 필요한 상태 보존
- [ ] 임의 셸 문자열을 실행하지 않고 고정된 운영체제 명령과 인자 사용
- [ ] 실제 실행 없이 요청·검증·결과 전달을 확인하는 모의 실행 모드 준비
- [ ] 접수·거절·실행 시작·오류를 `COMMAND_RESULT`로 전달
- [ ] 실제 제어를 명시적으로 허용한 테스트 PC에서만 종료·재부팅 확인
- [ ] 재부팅 후 다시 연결해 변경된 부팅 식별값 전송

**완료 기준:** 중복·만료·미허용 명령을 실행하지 않고, 승인된 테스트 PC 재부팅 후 재접속합니다. 실행 시작 응답만으로 재부팅 성공을 선언하지 않습니다.

### 6주 차: 배포와 최종 검증

- [ ] Windows 설치·설정·실행·종료·문제 해결 안내 작성
- [ ] PC 3대 30분 연속 테스트와 반복 재접속 확인
- [ ] 인증서 오류, 권한 부족, 측정 실패 사례와 해결 방법 정리
- [ ] 수집 코드·재연결 흐름·명령 처리 시연 자료 제공

**완료 기준:** 다른 팀원이 문서만 보고 자신의 테스트 PC에서 Agent를 실행하고 결과를 확인합니다.

## 협업 경계

| 상대 | B가 제공할 것 | 상대에게 받을 것 |
|---|---|---|
| A | 등록 정보, 측정값 예시, Heartbeat, 명령 결과, 부팅 식별값 | 접속·TLS 설정, 인증 절차, 공통 송수신 코드, 명령 규격 |
| C | 단위·수집 주기 설명, 정상·결측 데이터 예시, 부하·단절 시나리오 | 표시 이상 제보, 명령 상태 표시 요구사항 |

Agent는 서버에 연결하며 GUI와 직접 통신하지 않습니다. Agent 전용 복사본으로 통신 규격을 만들지 않고 `common/`을 함께 사용합니다. 서버 인증·라우팅은 A, 명령 전 확인 화면은 C가 담당합니다.

Windows 관리자 ID·비밀번호를 EC2에 넘겨 로그인하지 않습니다. 앱 관리자 인증과 Agent 토큰 인증은 구분하며, 실제 실행은 Agent 계정 권한을 사용합니다. A가 고정 IP·해당 SAN의 인증서·접속 설정을 전달하면 B는 검증을 유지한 상태로 연결합니다. 인증서 검증 비활성화는 사용하지 않습니다. 프로그램 시작은 후속 선택 기능이며 현재 구현 범위에 포함하지 않습니다.
