# C 담당 — 관리자 GUI·데이터

담당자: 미정

## 담당 목표와 범위

관리자가 PC별 상태·그래프·이력·경고를 확인하고 대상 PC에 종료·재부팅을 요청할 수 있는 GUI를 완성합니다. 주 작업 경로는 `admin_gui/`이며, 데이터 조회 요구사항·ERD 초안·발표 자료 취합도 담당합니다.

이 문서는 작업 배정안입니다. 아래 체크박스는 구현 완료를 의미하지 않습니다. 전체 일정은 [프로젝트 계획서](../project-plan.md)를 따릅니다.

## 먼저 할 일

1. PC 목록, 선택 PC 상세, 연결 상태를 포함한 와이어프레임을 만듭니다.
2. 샘플 데이터로 CPU·RAM 값을 표시하는 화면을 만듭니다.
3. 필요한 목록·상태·측정값 필드를 A·B와 확정합니다.
4. A의 서버에 연결해 샘플 데이터 대신 실제 Agent 값을 표시합니다.
5. 수신 작업을 별도 스레드로 분리하고 GUI 갱신은 메인 스레드에서 수행합니다.

## 주차별 작업과 완료 기준

### 1주 차: 화면과 데이터 요구사항

- [ ] CustomTkinter로 목록·상세·상태 영역 와이어프레임 작성
- [ ] 연결 중·정상·오프라인·오류·데이터 없음 화면 상태 정의
- [ ] 종료·재부팅 버튼과 대상·작업 확인 대화상자 설계
- [ ] 화면별 필요한 메시지와 필드를 A에게 전달
- [ ] B와 CPU·RAM 단위, 네트워크 Mbps, 측정 주기 확인

**산출물:** 와이어프레임, 화면별 필드 목록, 샘플 데이터 화면.

**완료 기준:** A·B가 화면에서 어떤 데이터가 필요한지 파악할 수 있습니다. 샘플 데이터임을 화면이나 실행 모드에서 구분합니다.

### 2주 차: 관리자 연결과 PC 목록

- [ ] 서버 TLS 검증, 관리자 인증, 연결 상태 표시 구현
- [ ] 수신 스레드 → `queue` → GUI 메인 스레드 갱신 구조 구현
- [ ] 초기 PC 목록과 접속·해제 이벤트 반영
- [ ] 서버 단절·인증 실패·인증서 오류를 구분해 표시
- [ ] 관리자 연결 복구 후 전체 목록을 다시 받아 상태 동기화
- [ ] 창 종료 시 연결·스레드·예약 갱신 정리

**완료 기준:** PC 3대의 접속·해제가 목록에 반영되고, 서버 응답을 기다리는 동안 창이 멈추지 않습니다.

### 3주 차: 대시보드와 그래프

- [ ] 선택한 PC의 CPU·RAM·업로드·다운로드·최신 시각 표시
- [ ] Matplotlib 그래프와 PC별 데이터 버퍼 구현
- [ ] 버퍼 길이·갱신 빈도를 제한해 장시간 실행 시 메모리 증가 방지
- [ ] PC 전환 시 다른 PC 데이터가 섞이지 않게 처리
- [ ] 오래된 데이터·결측 데이터 표시와 서버 단절 시 제어 비활성화
- [ ] 원래 측정 시각과 화면 수신 상태를 구분해 갱신 지연 표시

**완료 기준:** PC 3대 사이를 전환해도 값과 그래프가 정확한 PC에 대응하고, 단절 후 과거 값을 정상 최신값으로 표시하지 않습니다.

### 4주 차: 이력·ERD·경고

- [ ] `devices`, `metrics`, `events`, `commands` ERD와 조회 필드 초안을 A와 작성
- [ ] 최근 10분·1시간 이력 조회 조건과 서버 응답 규격 합의
- [ ] TCP/TLS로 이력 요청 후 그래프·표 표시; 조회 중·결과 없음·실패 상태 처리
- [ ] 서버가 판정한 임계치·오프라인 이벤트를 표시
- [ ] 중복 경고 억제·정상 복귀의 화면 동작을 A와 합의
- [ ] 조회 범위 변경 중 이전 응답이 도착하는 경우 잘못된 화면 반영 방지

**완료 기준:** 서버 재시작 후 저장된 이력을 조회하고, 같은 경고가 불필요하게 반복되지 않습니다.

### 5주 차: 원격 제어 화면

- [ ] 온라인 대상 PC를 선택한 경우에만 종료·재부팅 요청 허용
- [ ] 확인 창에 PC 이름·고유 ID·작업을 표시하고 취소 가능하게 구현
- [ ] 동일 요청의 중복 클릭을 막고 명령 ID별 진행 상태 관리
- [ ] 접수·거절·실행 시작·오류·시간 초과 상태를 구분해 표시
- [ ] 서버가 재접속과 부팅 식별값으로 확인한 재부팅 결과 표시
- [ ] 오프라인 전환만으로 종료·재부팅 성공을 표시하지 않기
- [ ] 단절 중 요청 결과가 불명확한 경우 자동으로 제어 명령을 재전송하지 않기

**완료 기준:** 대상·작업 확인 후 요청되고, 결과가 올바른 PC와 명령에 대응합니다. 모의 실행과 실제 제어를 구분합니다.

### 6주 차: 사용성·문서·발표

- [ ] 창 크기, 글자 가독성, 단위, 오류 메시지, 비활성 버튼 동작 점검
- [ ] PC 3대 30분 테스트에서 화면 멈춤·메모리 증가·잘못된 PC 표시 확인
- [ ] 관리자 설치·설정·실행·사용 매뉴얼 작성
- [ ] A·B의 결과를 받아 PPT·보고서·시연 영상 취합
- [ ] 발표 리허설에서 모니터링·경고·재부팅 연속 시연

**완료 기준:** 다른 팀원이 문서만 보고 GUI를 실행하고 주요 작업을 수행합니다. 발표 자료에는 실제 구현·검증한 내용만 포함합니다.

## 협업 경계

| 상대 | C가 제공할 것 | 상대에게 받을 것 |
|---|---|---|
| A | 화면 필드, ERD·조회 요구사항, 경고 표시 기준, 관리자 요청 | 인증·TLS 안내, 목록·상태·이력·경고·명령 결과 |
| B | 표시 이상 제보, 수집·명령 시연 요구사항 | 단위·주기·결측 예시, 부하·단절 테스트, 실행 결과 설명 |

SQLite 파일과 저장·조회 코드는 서버 측에서 A가 관리합니다. C는 스키마·조회 설계에 참여하고 GUI에서는 서버를 통해 조회합니다. GUI에 DB 파일 경로나 AWS 자격증명을 요구하지 않습니다.

경고 판정은 A의 서버가 수행하고 C는 표시를 담당합니다. GUI 단독 판정으로 서버 기록과 다른 경고가 발생하지 않도록 합니다. 서버의 권한 검증과 Agent의 실행 검증은 화면 버튼 제한과 별도로 필요합니다.
